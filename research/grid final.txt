2️⃣ Grid capital sourced only from RiskManager

Status: ⚠️ SPEC-COMPLIANT BUT RISKY

Correct behavior

trading_bot.py::_execute_grid_signal()

grid_capital = self.risk_manager.get_grid_capital(
    account_balance, current_exposure, symbol
)
signal.grid_capital = grid_capital  # overrides strategy value


Risky detail

RiskManager.validate_grid_exposure() uses:

account_balance = getattr(self, '_account_balance', 10000)


This is not guaranteed to be the real account balance and can drift.

Why this matters

Exposure math can silently pass when it should fail.

This is a latent capital limit violation risk, not theoretical.

Concrete fix

# risk_manager.py
def validate_grid_exposure(self, symbol, proposed_grid_capital, account_balance, current_exposure):
    ...


Then call it from TradingBot with real balance:

self.risk_manager.validate_grid_exposure(
    symbol, grid_capital, account_balance, current_exposure
)

3️⃣ Per-level sizing math correctness

Status: ⚠️ SPEC-COMPLIANT BUT INCOMPLETE

What’s correct

Equal allocation enforced:

capital_per_level = grid_capital / signal.grid_levels


No martingale behavior.

Levels are normalized in RiskManager.normalize_grid_params().

Missing guarantee

There is no hard assertion that:

Σ(level notionals) ≤ grid_capital


Concrete fix
Add a post-build check before placing orders:

total_allocated = sum(level["notional"] for level in grid_levels)
if total_allocated > grid_capital:
    raise RuntimeError("Grid allocation exceeds approved capital")

4️⃣ Emergency stop placement + unwind on failure

Status: ❌ SPEC-BREAKING

Problem A — Emergency stop not proven FIRST

In trading_bot.py::_execute_grid_signal() the file cuts off before:

Stop placement confirmation

GridLifecycleManager.register_new_grid() call

You intend to do:

“PLACE EMERGENCY STOP FIRST (MANDATORY)”

But no hard fail is visible that aborts grid creation if stop placement fails.

Problem B — Lifecycle not registered atomically

Spec requires:

Grid exists only after emergency stop is live

That means:

place emergency stop → confirm → register grid → place grid orders


Concrete fix
Enforce this order strictly:

stop_order = place_emergency_stop(...)
if not stop_order or not stop_order["id"]:
    raise RuntimeError("Emergency stop placement failed")

self.grid_lifecycle.register_new_grid(symbol, grid_capital, stop_price)


No grid orders should exist before this succeeds.

5️⃣ Regime auto-disable → cancel orders + flatten

Clears exposure

Missing link

MarketRegimeDetector does not call GridLifecycleManager.on_regime_disallowed()

TradingBot does not enforce regime → lifecycle transitions

Concrete fix
In trading loop (or signal loop):

if regime not in ALLOWED_GRID_REGIMES:
    self.grid_lifecycle.on_regime_disallowed(symbol)


Right now, grids can continue running silently through a bad regime.

Without checking GridLifecycleManager

Concrete fix
Add a hard gate:

if self.grid_lifecycle.has_active_grid(symbol) and signal.strategy != GRID_TRADING:

Grid must be exclusive owner of symbol execution.
