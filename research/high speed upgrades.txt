Adding standard deviation bands around the VWAP is a high-value enhancement for the VWAP Scalping strategy. These bands create dynamic overbought/oversold zones, improve mean-reversion filtering, and help identify statistical extremes — exactly as recommended in the 2026 research and common in professional setups (TrendSpider, thinkorswim, TradingView VWAP+SD implementations).
Why Add VWAP Bands?

+1/−1 SD ≈ 68% of price action (normal range)
+2/−2 SD ≈ 95% — strong reversion candidates when price reaches outer bands
+3/−3 SD ≈ very rare extremes (exhaustion/reversal zones)
In crypto/perps (high volatility), bands adapt better than fixed % thresholds
Complements your existing ATR-based deviation check while adding volume-weighted statistical context

Calculation Method (Chosen Approach)
From platform implementations (thinkorswim, TrendSpider, multiple Pine Script examples):
VWAP bands use a volume-weighted variance approach:

VWAP = cumulative (price × volume) / cumulative volume
(already using typical price = (H+L+C)/3)
Variance = [cumulative (volume × (price - VWAP)²)] / cumulative volume  −  VWAP²
(more precisely: second moment minus square of first moment)
StdDev = sqrt(variance)
Upper band N = VWAP + multiplier × StdDev
Lower band N = VWAP − multiplier × StdDev

This is the volume-weighted standard deviation — the most common and theoretically sound method for VWAP bands (matches thinkorswim, many TradingView scripts, and institutional tools).
Alternative (simpler but less accurate): sqrt( cumulative (volume × (price - VWAP)²) / cumulative volume )
Many platforms use this approximation; it's close when VWAP is stable.
We'll implement the precise version.

# ... existing imports ...

class VWAPScalpingStrategy(BaseStrategy):
    def __init__(self,
                 atr_period: int = 14,
                 atr_multiplier_entry: float = 1.2,
                 atr_multiplier_sl: float = 1.5,
                 macd_fast: int = 12, macd_slow: int = 26, macd_signal: int = 9,
                 vwap_sd_multipliers: list = [1.0, 2.0, 3.0],   # bands to compute
                 cooldown_minutes: int = 8,
                 min_confidence: float = 0.62):
        super().__init__()
        self.strategy_type = StrategyType.VWAP_SCALPING
        # ... existing params ...
        self.vwap_sd_mults = vwap_sd_multipliers  # e.g. [1,2,3]

    def calculate_vwap_and_bands(self, df: Any) -> Dict[str, float]:
        """
        Compute VWAP + multiple standard deviation bands (volume-weighted)
        Expects pandas DataFrame with 'high','low','close','volume'
        Returns dict: {'vwap': ..., 'sd1_upper':..., 'sd1_lower':..., 'sd2_upper':..., ...}
        """
        if len(df) < 20 or 'volume' not in df.columns:
            return {}

        typical = (df['high'] + df['low'] + df['close']) / 3
        pv = typical * df['volume']                    # price × volume
        cum_pv = pv.cumsum()
        cum_vol = df['volume'].cumsum()

        vwap = cum_pv / cum_vol

        # For volume-weighted variance:
        # squared_dev = volume * (typical - vwap)^2
        # But vwap is cumulative → we need to compute running variance carefully

        # Practical implementation (common in indicators):
        # variance = [cum(vol * typical^2) / cum(vol)] - vwap^2
        price_sq_vol = typical.pow(2) * df['volume']
        cum_price_sq_vol = price_sq_vol.cumsum()

        variance = (cum_price_sq_vol / cum_vol) - vwap.pow(2)
        variance = variance.clip(lower=0)  # avoid floating-point negative

        stddev = variance.pow(0.5)

        result = {'vwap': vwap.iloc[-1]}
        for mult in self.vwap_sd_mults:
            result[f'sd{mult}_upper'] = vwap.iloc[-1] + mult * stddev.iloc[-1]
            result[f'sd{mult}_lower'] = vwap.iloc[-1] - mult * stddev.iloc[-1]

        return result

    def generate_signal(self,
                        symbol: str,
                        timeframe_data: Dict[str, Any],
                        current_position: float = 0,
                        **kwargs) -> Optional[Signal]:
        if '1m' not in timeframe_data or '5m' not in timeframe_data:
            return None

        df1 = timeframe_data['1m'].copy()  # ensure we don't modify original
        df5 = timeframe_data['5m']

        if len(df1) < 30 or len(df5) < 40:
            return None

        # === VWAP + Bands (1m timeframe - most responsive) ===
        bands = self.calculate_vwap_and_bands(df1)
        if not bands:
            return None

        vwap = bands['vwap']
        current_price = df1['close'].iloc[-1]

        # Distance to VWAP (in ATR units for normalization)
        atr_1m = calculate_atr(df1['high'], df1['low'], df1['close'], period=self.atr_period)[-1]
        deviation_atr = abs(current_price - vwap) / atr_1m if atr_1m > 0 else 0

        # === Band position checks ===
        in_sd1 = bands['sd1_lower'] <= current_price <= bands['sd1_upper']
        outside_sd2 = (
            current_price > bands.get('sd2_upper', float('inf')) or
            current_price < bands.get('sd2_lower', float('-inf'))
        )
        near_sd3 = (
            abs(current_price - bands.get('sd3_upper', 0)) < atr_1m * 0.3 or
            abs(current_price - bands.get('sd3_lower', 0)) < atr_1m * 0.3
        )

        # === MACD confirmation (5m) ===
        macd_line, signal_line, hist = calculate_macd(df5['close'], *self.macd_params)
        macd_hist_now = hist[-1]
        macd_hist_prev = hist[-2] if len(hist) > 1 else 0

        side = None
        notes = []

        if current_price < vwap and deviation_atr > self.atr_mult_entry:
            # Below VWAP → Long bias (reversion up)
            if macd_hist_now > 0 and macd_hist_now > macd_hist_prev:  # bullish confirmation
                if outside_sd2 or near_sd3:
                    # Extreme → higher conviction
                    side = OrderSide.BUY
                    notes.append("Extreme lower deviation (SD2+)")
                elif not in_sd1:
                    side = OrderSide.BUY
                    notes.append("Outside SD1 lower")

        elif current_price > vwap and deviation_atr > self.atr_mult_entry:
            # Above VWAP → Short bias
            if macd_hist_now < 0 and macd_hist_now < macd_hist_prev:
                if outside_sd2 or near_sd3:
                    side = OrderSide.SELL
                    notes.append("Extreme upper deviation (SD2+)")
                elif not in_sd1:
                    side = OrderSide.SELL
                    notes.append("Outside SD1 upper")

        if not side:
            return None

        # === Build signal ===
        entry_price = current_price
        stop_loss = vwap if side == OrderSide.BUY else vwap
        if side == OrderSide.BUY:
            stop_loss = min(stop_loss, current_price - atr_1m * self.atr_mult_sl)
        else:
            stop_loss = max(stop_loss, current_price + atr_1m * self.atr_mult_sl)

        take_profit = vwap  # primary target = mean reversion to VWAP
        # Optional: partial TP at SD1 opposite band

        confidence = 0.65 + min(0.25, deviation_atr * 0.12)
        if outside_sd2:
            confidence += 0.12
        if near_sd3:
            confidence += 0.15
        confidence = min(0.94, max(self.min_confidence, confidence))

        signal = Signal(
            strategy=self.strategy_type,
            asset=symbol,
            side=side,
            entry_price=entry_price,
            stop_loss=stop_loss,
            take_profit=take_profit,
            confidence=confidence,
            quality=TradeQuality.HIGH if confidence > 0.80 else TradeQuality.STANDARD,
            timeframe="1m",
            market_state="vwap_reversion",
            notes=" | ".join([f"VWAP ${vwap:.4f}", f"dev {deviation_atr:.2f}×ATR"] + notes)
        )

        return signal

What is Level 2 Data? (Order Book Depth)
Level 2 market data (also called market depth, depth of book, or L2 quotes) shows the full visible order book beyond just the best bid and best ask (which is Level 1).

Level 1: Only top bid price + size, top ask price + size (your current get_ticker_ws approximates this).
Level 2: Multiple price levels on both sides (e.g., top 10–50 bids and asks), including:
Price levels
Quantity (size) at each level
Sometimes aggregated or individual orders (market-by-price vs market-by-order)


In crypto perpetuals/DEXes (like Pacifica on Solana):

Many order-book DEXs (Drift, Phoenix, Openbook derivatives) expose on-chain or WebSocket Level 2 depth.
It shows real-time supply/demand walls, potential support/resistance, and absorption (e.g., large buy wall getting eaten → bullish pressure).
For Order Book Imbalance strategy: You calculate something like
imbalance = (sum bid sizes top N levels) / (sum bid + sum ask sizes)
→ >0.6 → buy pressure → long bias
→ <0.4 → sell pressure → short bias
Often combined with delta (aggressive buys vs sells hitting the book).

Pacifica-specific note: As a Solana perp DEX (similar to Drift/Phoenix patterns), it likely provides WebSocket order book snapshots/updates (depth levels configurable, e.g., 10–20). Your pacifica_ws_client.py probably already subscribes to ticker — extending it to depth channels is the main lift.
If Pacifica lacks deep L2 (some Solana perps are hybrid AMM/order-book), fallback options include shallower imbalance proxies (e.g., bid/ask spread changes + volume delta).

How to Use It for Order Book Imbalance Strategy
Typical imbalance formula (top N levels):
Pythondef calculate_imbalance(bids: list, asks: list, levels: int = 5) -> float:
    """
    imbalance = (sum bid quantities top N) / (sum bid qty + sum ask qty top N)
    > 0.6 → strong buy pressure
    < 0.4 → strong sell pressure
    """
    bid_vol = sum(float(level["a"]) for level in bids[:levels])
    ask_vol = sum(float(level["a"]) for level in asks[:levels])
    total_vol = bid_vol + ask_vol
    if total_vol == 0:
        return 0.5  # neutral
    return bid_vol / total_vol

Subscribe with agg_level: 10 or 1 for usable depth
Maintain local book state (merge incremental updates — doc implies delta-style at 100ms)
Trigger signals when imbalance crosses thresholds (e.g. >0.65 long, <0.35 short) + confirmation (price momentum, volume spike)
Use "n" (order count) as secondary filter — high n + low a → potential spoofing/wall

Comparison to "True" Level 2:

Not raw individual orders (L3) → no order-by-order tracking
But aggregated by price → still very effective for imbalance (most strategies use top 5–20 levels anyway)
